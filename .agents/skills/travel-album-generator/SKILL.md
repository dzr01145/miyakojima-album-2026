# Travel Album Generator (旅行Webアルバム自動生成スキル)

## 概要
スマートフォンやデジカメ等で撮影された大量の写真・動画から、旅程やスポットごとの高品質なWebフォトアルバムを全自動で構築・公開します。
旅の臨場感を伝えるポップな旅程ルートマップや、共有用QRコード、左サイドバーナビゲーション、プライバシー保護機能を網羅したフル機能のアルバムをワンストップで生成します。

---

### 主な特徴と自動化機能

1. **EXIF・タイムスタンプ自動解析 & スポット自動分類**:
   - 撮影日時、GPS座標を自動抽出。
   - 移動時間ギャップ（20〜30分以上の間隔）や位置情報をもとにスポット（[A], [B], [C]...）へ自動クラスタリング。

2. **人事対策・プライバシー保護プロトコル（徹底配慮）**:
   - **撮影時刻の完全排除**: 「遊んでいる」と人事や職場等から誤認されないよう、画面上の時刻（`⏰ 12:22 - 12:31`, `🕒 12:22:06` 等）を完全非表示。
   - **実ファイル名の連番リネーム**: 撮影日時がバレてしまうファイル名（`PXL_20260424_...`）を、安全なスポット連番（`{project}_A01.jpg`, `{project}_C01.mp4` 等）へ実ファイルごと一括リネーム。
   - **日付表記のユーザー確認**: 具体的な年月日を出すか、「Day 1 / Day 2」などの日程番号にするかを **`ask_question` ツールでユーザーに確認**。

3. **ポップな旅程ルートマップ（イラスト風SVGマップ）**:
   - **宮古島等の全体地形SVG**: エメラルドグリーンの浅瀬・サンゴ礁、主要道路、橋（伊良部大橋、来間大橋、池間大橋等）、波のCSSアニメーション、方位磁針、スケールバーを装備。
   - **日程別ルートライン**: Day 1（ローズ）、Day 2（シアン）、Day 3（アンバー）の破線アニメーションで移動順序（矢印付き）を可視化。
   - **インタラクティブ・ピン**:
     - 各スポットのポップなピン（[A]〜[N]）と吹き出しラベル。
     - ピンをクリックすると各スポットセクションへスムーズスクロール＆ハイライト枠線アニメーション。
     - **ジッター（震え）防止仕様**: ホバー時のCSS `transform: scale()` による座標ブレ・震え現象を完全防止（不可視ヒットボックス＋枠線・カラー変化でスムーズに表現）。
   - **日程切り替えフィルター**: 「全日程」「Day 1」「Day 2」「Day 3」ボタンで特定日のルートとピンのみを強調表示。

4. **シームレスなナビゲーション機能**:
   - **左サイドバー上部タイトル**: 「🌴 タイトル / スポット案内」エリアをクリックすると、ページ最上部（Heroヘッダー）へスムーズスクロールで復帰（モバイルドロワーは自動閉鎖）。
   - **左サイドバー最上部マップリンク**: 「🗺️ 全体ルートマップ」リンクからいつでもワンクリックでマップへジャンプ。
   - **フローティング「🗺️ マップへ戻る」ボタン (FAB)**: スクロールしてルートマップを通り過ぎると画面右下に出現し、ワンタップで即座にルートマップへ戻れる。

5. **高速表示Web最適化**:
   - 画像: 長辺1600px（品質80）のWeb用画像と400pxサムネイルを自動生成。EXIFの向き（Orientation）を自動補正。
   - 動画: H.264/AAC（2MB未満目標）へ自動圧縮。オリジナル原本は安全に退避・保管。

6. **Glassmorphism QRコードカード & 拡大モーダル**:
   - 公開URLのQRコードをHeroヘッダー下に配置。
   - ワンクリックURLコピー、QRコード拡大モーダル、QR画像保存機能を完備。

7. **写真のない施設（撮影禁止等）のリッチリンク対応**:
   - 写真が撮影できないスポット（地下ダム資料館等）は、外部リンク（公式サイトや紹介記事）へのスマートなリンクカードとして案内。

8. **フルスクリーン・ライトボックス**:
   - キーボード（← / → / ESC）やスワイプで前後の写真・動画を高画質閲覧。Google Maps撮影地リンク連携。

9. **不要写真・重複整理アシスタント**:
   - 削除候補のチェックボックスから一括削除PowerShellコマンドを生成可能。

## ワークフロー手順

### ステップ 1: 写真・動画のスキャンとスポット自動分類
撮影メディアが置かれたフォルダを指定してスキャンし、`album_data.json` を生成します。
```bash
python .agents/skills/travel-album-generator/scripts/process_album.py scan --input-dir <写真フォルダ> --output album_data.json --title "〇〇 トリップアルバム"
```

### ステップ 2: 日付・プライバシー方針のユーザー確認（★必須: ask_question）
アルバムをビルドする前に、**必ず `ask_question` ツールを使用してユーザーに日付表記やプライバシー方針を確認**します。

#### 質問例:
```json
{
  "questions": [
    {
      "question": "日付（年月日）の表示について、どのように扱いますか？",
      "options": [
        "(推奨) 具体的な日付を伏せ、「Day 1」「Day 2」「Day 3」などの日程表記にする（人事・プライバシー対策）",
        "具体的な日付（2026/04/23など）を表記する",
        "日付も含めて時間・日程に関する表記をすべて非表示にする"
      ],
      "is_multi_select": false
    },
    {
      "question": "ファイル名および撮影時刻の表示・リネームについて、どちらにしますか？",
      "options": [
        "(推奨) 画面からファイル名・時刻を完全に非表示にし、実ファイル名も連番（例: miyako_A01.jpg, miyako_A02.mp4）へ一括リネームする",
        "画面上のファイル名・時間表示のみを非表示にする（実ファイルのリネームは行わない）",
        "元のファイル名と時刻をそのまま表示する"
      ],
      "is_multi_select": false
    }
  ]
}
```

### ステップ 3: メディアのWeb最適化 & 連番リネーム
- ユーザーの回答に応じて、実ファイル名を連番（例: `{project}_A01.jpg`）にリネームし、`album_data.json` を更新。
- Web表示用の軽量画像（`images/web/`）、サムネイル（`images/thumb/`）、動画圧縮（`videos/`）を実行します。
```bash
python .agents/skills/travel-album-generator/scripts/process_album.py optimize --data album_data.json
```

### ステップ 4: 旅程メモ・スポット情報・外部リンクの反映
ユーザーから提供された旅程メモ（食事場所、観光スポット名、感想など）や、写真のない施設への外部リンクURLを `album_data.json` の各スポット（`title`, `note`, `map_query`, `external_link`）にマッピングします。

### ステップ 5: QRコードの生成
Webアルバムの公開先URLが決まったら、QRコードを自動生成します。
```bash
python .agents/skills/travel-album-generator/scripts/process_album.py qr --url "https://<username>.github.io/<repo>/"
```

### ステップ 6: WebアルバムHTMLの完全自動ビルド
ビルドコマンドを実行して、ルートマップ・サイドバー・FAB・ライトボックスを統合した `index.html` を作成します。
```bash
python -X utf8 .agents/skills/travel-album-generator/scripts/process_album.py build --data album_data.json --output index.html
```
- **自動装備される仕様**:
  - ポップな旅程ルートマップ（SVG地形・波アニメーション・日程別ルート・ジッター防止ピン）
  - 左サイドバー最上部の「🗺️ 全体ルートマップ」リンク
  - 左サイドバー上部タイトル（「🌴 タイトル / スポット案内」）およびモバイルヘッダーの「トップへ戻る」クリック機能
  - スクロール追従のフローティング「🗺️ マップへ戻る」ボタン（FAB）
  - ユーザーの選択に応じた日程表記（Day 1 / 具体日付 / 非表示）
  - 時刻（⏰ 12:22等）およびファイル名の完全非表示
  - ファイルは必ず **UTF-8 (BOMなし)** で保存

### ステップ 7: ブラウザ検証 & GitHub / Render 公開
1. Playwright 等でデスクトップおよびモバイルのレイアウト・スクロール動作を自動検証。
2. `git add`, `git commit`, `git push` を行い、GitHub Pages または Render で即時公開。

## 遵守事項・ベストプラクティス
- **アスクユーザークエスチョン**: 日付の表記方法（Day 1表記 / 具体日付 / 非表示）およびファイル名のリネーム範囲は、必ず `ask_question` でユーザーの好みをヒアリングすること。
- **テキストエンコーディング**: すべてのテキストファイル（HTML/JSON/MD/Python等）は必ず **UTF-8 (BOMなし)** で保存すること。
- **元ファイルの保護**: 原本写真や高画質元動画は絶対に上書きせず、`VOID/` または `originals/` フォルダへ退避保管すること。
- **プライバシー保護**: 個人情報や不要なメタデータ、勤務時間と誤認されるおそれのあるタイムスタンプが公開リポジトリに含まれないよう徹底検証すること。
- **操作性（UX）の担保**: ルートマップピンのホバー時に震え（ジッター）が発生しないよう、不可視のパディングヒットボックスと静的座標を維持すること。\n
